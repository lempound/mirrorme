# spec/questions-v1 —— 访谈问题库（规范）

> 版本：**v0.1-draft**
> 数据：`spec/questions-v1.yml`
> 作用：问题库决定模型能长成什么样。**问题问错了，后面所有工程都是白费。**

---

## 0. 一条总原则

> **只问具体事例，不问抽象看法。**

| 类型 | 例子 | 能不能用 |
|---|---|---|
| ✅ 具体事例 | "上一次你明知道该做却没做，是哪件事？" | 能 |
| ❌ 抽象看法 | "你怎么看待拖延？" | 不能 |

原因：抽象看法可以被任何人编出来，包括 AI，也包括你自己的合理化；**具体经历编不出来**。

## 1. 四类问题

| 类别 | 用途 | 示例 | 写入 |
|---|---|---|---|
| **init** 建档 | 首次初始化，10 问 | 见 §2 | `self/*` 骨架 + `config` |
| **weekly** 常规 | 每周 20 分钟，4 问 | 见 §3 | `notes/*` 第 3/4 段 |
| **decision** 决策 | 遇到岔路口时 | `situation` 类 | `self/decisions/` |
| **probe** 追问 | 回答太短/太抽象时 | "能举个例子吗？" | 同上 |

## 2. init 十问（`mirrorme init`）

顺序经过设计：**先事实 → 后观点；先具体 → 后抽象；先安全 → 后敏感。**

| # | 问题 | 生成物 | 设计意图 |
|---|---|---|---|
| 1 | 你希望我怎么称呼你？ | `identity.name` | 建立称呼，降低疏离 |
| 2 | 你现在最想搞明白的三件事是什么？ | `taxonomy` 种子 + MOC | 用"想搞明白"代替"关心什么"，更具体 |
| 3 | 过去一年，你做过最不后悔的一个决定是什么？为什么？ | `values.md` + 首条 `decision` | 价值观只能从真实取舍里反推 |
| 4 | 什么事会让你立刻改变主意？ | `principles.md` 种子 | 反例比主张更能定义一个人 |
| 5 | 你说话有什么口头禅或习惯？ | `voice.md` 种子 | 表达指纹 |
| 6 | 有没有你明确不想讨论、也不想被代表的部分？ | `unknowns.md` + `LEGACY.md` | **边界即人格**，先划红线 |
| 7 | 你希望它将来替你回答什么问题？ | 保真度目标 + `eval/questions.yml` | 从使用场景反推需求 |
| 8 | 哪些内容永远不能公开？ | `privacy.never_export` | 隐私必须在建档时确定 |
| 9 | 你打算多久记一次？ | `fidelity.interview_weekly_minutes` | 承诺要现实 |
| 10 | 你现在用什么 AI 工具？ | `agents.targets` | 决定生成哪些入口文件 |

**规则**：任何一问用户都可以跳过。跳过的问题进入 `unknowns.md`，**不追问**。

## 3. weekly 问题池

按用途分七类，每次从中选 4 个。**选题由 engine 按 §4 算法决定，不是固定顺序。**

| 类别 | 问题模板 | 目的 |
|---|---|---|
| **溯源** | "这个观点是你自己想出来的，还是从哪看来的？" | 区分原创与转述 |
| **反例** | "什么情况下你会不这么做？" | 把原则变成有边界的规则 |
| **变迁** | "三年前的你会同意这句话吗？" | 捕获成长，生成 `position` 历史 |
| **代价** | "按这个原则做事，你放弃过什么？" | 验证原则是不是真的 |
| **情绪** | "这件事当时让你什么感觉？" | 采集 `affect.md` |
| **边界** | "有没有你明确不想改变的部分？" | 更新 `unknowns.md` |
| **具体** | "能举一个你实际这么做的例子吗？" | 最重要，可反复使用 |

**配比**：每次 4 问 = 3 个"具体/反例" + 1 个"溯源/变迁"。**不允许全是抽象类问题。**

---

## 4. 选题算法（engine 实现）

优先级从高到低：

1. **缺口优先**：`self/` 中为空的文件（如 `affect.md` 没有内容）→ 优先出该类问题
2. **超期优先**：`seed` 状态超过 `lifecycle.seed_ttl_days` 的笔记 → 出"具体"类追问
3. **维度均衡**：最近 30 天没被提及的 `domain` → 优先
4. **去重**：最近 4 周问过的问题不再问
5. **随机扰动**：同优先级内随机，避免每次顺序一样

**终止条件**：用户连续 2 次回答"跳过"，本次访谈立即结束，不劝。

---

## 5. 禁止的问题类型

| 禁止 | 原因 |
|---|---|
| 是非题（"你是不是……？"） | 信息量太低 |
| 一次问两件事 | 回答会只覆盖一个 |
| 涉及第三方隐私且未授权 | 伦理红线（见 `docs/ethics.md`） |
| "你觉得 X 怎么样" | 诱导抽象空话 |
| 让用户评价自己"是什么样的人" | 自我认知 ≠ 行为证据 |
| 追问情绪创伤细节 | 访谈不是心理咨询 |

---

## 6. 追问规则

满足任一条件时，必须追问一次：

| 条件 | 追问 |
|---|---|
| 回答 < 15 字 | "能展开说一句吗？" |
| 回答只有结论没有过程 | "当时你是怎么想的？" |
| 回答全是抽象词 | "能举个具体例子吗？" |
| 出现"应该""一般来说" | "你自己实际是怎么做的？" |

**只追问一次**。第二次仍无具体内容，记录为 `unknowns` 并结束该题。

---

## 7. 输出契约

`questions-v1.yml` 的字段定义：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 全局唯一，如 `q-weekly-03` |
| `phase` | enum | ✅ | `init｜weekly｜decision｜probe` |
| `category` | enum | ✅ | 见 §3 七类 |
| `text` | string | ✅ | 问题正文 |
| `why` | string | ✅ | 这个问题的设计意图（给 engine 选题用） |
| `target` | string | ✅ | 回答写入的位置 |
| `followups` | string[] | ❌ | 追问模板 |

---

## 8. 演进

问题库可以随时增删（属于 minor 变更）。但**删除问题不删除已采集的数据**。
新增问题必须写 `why`——说不出设计意图的问题不进库。
